# YAML-backed answer prompts

## Goal

Move the `answer_v1` prompt definition out of Python and into a versioned YAML
file, while preserving the existing `render_answer_prompt()` call site and its
safe handling of retrieval context.

## Prompt format

`src/company_knowledge_rag/prompts/answer_v1.yaml` contains four required
string fields:

- `id`: stable prompt identifier (`answer`)
- `version`: prompt version (`v1`)
- `system_instruction`: provider system instruction
- `user_template`: user-message template

The only permitted template placeholders are `{{ context }}` and
`{{ question }}`. The template is content configuration, not executable code.

## Runtime design

A Python loader reads the packaged YAML file with `yaml.safe_load` and
validates the required fields and allowed placeholders. Invalid or missing
configuration fails clearly during prompt rendering.

The renderer continues to build `context` in Python from `Chunk` objects, so
citation identifiers such as `[C1]` remain generated by trusted application
code. It substitutes `context` and `question` without evaluating expressions.
It returns the existing `RenderedPrompt` shape and retains a stable
`PROMPT_VERSION` for tracing and evaluation.

## Dependencies and packaging

Add PyYAML as a direct production dependency. Include YAML prompt files in the
wheel package so behavior is the same in source checkouts and deployed builds.

## Compatibility and tests

`ChatService` continues to call `render_answer_prompt()` without API changes.
Tests cover a successful YAML render, citation-preserving context generation,
and rejected invalid schema or unsupported placeholders.

## Scope

This change migrates only `answer_v1`. It does not add a general prompt
registry, remote prompt management, or runtime prompt editing.
